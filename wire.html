The wire protocol

Every frame is one envelope, serialized as canonical JSON and length-prefixed on TCP. The normative text is SPEC/wire-v1.md. These three rules are what a new chain relies on.

Frame

+-----------------+---------------------------+
| length (4 bytes)| canonical JSON body       |
| big-endian u32  | exactly `length` bytes    |
+-----------------+---------------------------+

Envelope

{
  "alg": "schnorr",
  "data": {"n": 1},
  "id": "<64 hex>",
  "pk": "<64 hex>",
  "sig": "<128 hex>",
  "ts": 1757430000000,
  "type": "app.counter",
  "v": 1
}

Three properties

  • Canonical JSON. Sorted keys, no whitespace, no floating point. The bytes are the message.
  • Content addressing. id is sha256 of the canonical payload. A relay may rebuild an envelope without breaking deduplication.
  • Version negotiation. ctl.hello runs on every connection. A peer speaking a version that cannot be served is disconnected.

Signatures cover the 32-byte id. Schnorr is BIP-340. Ed25519 is RFC 8032. Control messages are never relayed. Application objects sit on top of this frame and are applied only after every message in the batch validates.
